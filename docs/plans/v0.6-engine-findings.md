# Ledger — engine deficiencies & bugs surfaced by the v0.6 CS slice

The owner's mandate: authoring the slice doubles as an engine audit. Every
phase's review adjudicates each friction point as ENGINE-BUG (engine violates
its own spec), ENGINE-GAP (spec-silent, blocks natural authoring),
FROZEN-QUIRK (spec pins it; content lives with it), or CONTENT-ERROR. Engine
BUG/GAP items get a disposition: FIX (queued/landed, with commit) / IDIOM
(documented authoring shape) / LINT (content tooling) / DOC-NOTE.

## Found in Phase A (foundations + season wheel)

- **E1 · ENGINE-GAP · missing attr compares as absent, not 0** —
  `Pred::Cmp` on a living card's numeric attr yields false when the entry is
  missing (`src/core/predicate.rs` Cmp eval, "either operand missing →
  false"), while §9.31 SET-delta semantics and `total()` both treat missing
  as 0. Spec §6.3 is silent on attr-path comparisons (§9.39 pins aspects
  only). Consequence: a `silver < cost` broke-gate cannot be authored
  correctly for a first-time buyer (script entities mint empty attrs), and no
  content workaround exists.
  **Disposition: FIX LANDED** — living-card numeric attr reads read 0 when
  absent (behavior-preserving for every `>=`/`!=` gate in the two shipped
  scripts; `<` gates become correct).
- **E2 · ENGINE-GAP (minor) + IDIOM · RUN hand-off has no context binding** —
  §9.47 re-evaluates a candidate's `when:` against the post-outcome draft,
  and the shadow lint rejects identical whens, so every wheel dispatch target
  needed a synthetic world-marker when (`exists(name:THE_TURNING) AND …`,
  `count(actors) >= 1` vs `= 1` as lint noise). **Disposition: IDIOM** — the
  better content shape (keep the season card alive through its judge; judges
  gate on `exists(name:SEASON_…)`) lands with Phase B; doc note in the plan.
- **E3 · FROZEN-QUIRK · REPLACE refuses entities; trigger-body failure
  freezes the clock** — `REPLACE X WITH <entity>` refuses ("no kind",
  engine.rs REPLACE arm; §9.33 pins prototype successors), and a never-alive
  prototype inside a trigger body fails the whole advance pass forever
  (events have no window-refuse; §9.19/§9.32 severity). **Disposition:
  DOC-NOTE** (plan law 1 already pins DESTROY+SPAWN+SET restores) + future
  lint candidate.
- **E4 · FROZEN-QUIRK · silent chain death** — a weather with no matching RUN
  candidate ends the wheel with no diagnostic (§9.47's "that is CS's chain
  ending"). A content drift (rename, cardinality) would silently stop the
  seasons. **Disposition: LINT candidate** (warn on RUN-target whens with
  bare `count(role)` gates) + §8 doc note.
- **E5 · FROZEN-QUIRK (cosmetic) · follow-up rows render dead parent
  bindings** — a RUN follow-up's BEGIN row prints the parent's authored refs
  even when a bound card died mid-parent-window. **Disposition: DOC-NOTE.**
- **E6 · minor content-side input laxity** — bare clock input accepts hours
  > 23 (`0:118`) in the lenient parser. **Disposition: none** (lenient-input
  domain, pre-existing).

## Found in Phase B (study ladder + dreams + the Bellwood)

- **E7 · ENGINE-GAP · RUN follow-ups inherit ALL parent refs, locking the
  bootstrap card forever** — the synthesized follow-up clause carries every
  committed role (`refs_to_clause`, engine.rs:1909-1923), so the wheel chain
  (weather→time.turn→weather) keeps an open WAIT window holding
  `with=VIGOR` at all times; a restored VIGOR mint re-locks by name and
  dream.rest_vigor then §9.19-rejects. Worse, the synthesized clause is not a
  shape a player step could produce (WAIT declares actors only), so §9.47's
  "the same shape a player step produces" is violated by the implementation's
  wholesale inheritance. Bites ~70% of games (labor roll > 3).
  **Disposition: FIX LANDED** — inherited refs are PROJECTED onto the
  candidate verb's declared slots at clause build (`refs_to_clause`, engine.rs):
  a role the candidate verb does not declare is dropped from the inherited
  clause and so never locks; actors survive wherever declared (time.turn reads
  actors' silver), same-verb chains keep every role (the projection is the
  identity), the parent window's own refs and locks are untouched. Ruling 47's
  semantics bullet amended; pinned in tests/run_chains.rs (cross-verb
  projection + the slice-shaped bootstrap chain).
- **E8 · ENGINE-GAP (minor) + IDIOM · RUN candidates cannot see the parent's
  bindings** — candidate whens evaluate against the post-outcome world, not
  the hand-off, and §9.48's completion triggers (which DO see window
  bindings) fire only on BEGIN-committed cards — never on a card the parent
  just DREW. CS's dream_router shape (draw → linked keyed on the drawn
  element) is thus inexpressible in one step; the slice routes on bound-mood
  selection instead. **Disposition: IDIOM + DOC-NOTE** (future want: candidate
  whens may read parent-window bindings).
- **E9 · ENGINE-GAP (input laxity) · lenient binding fills two roles from one
  card** — `alive_names` resolves each name to its OLDEST copy only
  (session/lenient.rs:384-398), so `combine the psalm and the psalm` binds
  one card twice: the combine consumes it once, mints the 6, and leaves the
  stray (bounded +4 magnitude distortion; would let a rite pool one card N
  times). **Disposition: DOC-NOTE + Phase C pins `count(with)` on rites;**
  lint candidate (warn when one id fills two roles at commit).
  **Phase C addition — the cross-role residue.** The commit-time placement
  refusal is PER-ROLE (`placed` is a HashSet rebuilt inside each role's
  loop, engine.rs), so one card binds into two DIFFERENT roles cleanly:
  observed on the win-walk file, a lone fragment self-combines
  (`study a candle psalm with a candle psalm` → object = with = the oldest
  copy; the 2+2 pair row fires on one card, mints the 6, consumes the card
  once, leaves the second copy as a stray — a whole 2→6→18 ladder climbable
  from a single book), and same-card `to`+`with` is accepted on USE_ON
  (benign today — the desire cards carry no pooled magnitudes). The
  same-role placement refusal and the rite count pins do NOT cover
  cross-role: predicates have no card-identity test, so no `when:` can see
  that `object` and `with` hold the same id. **Disposition (amended): the
  STUDY pair rows now pin `count(object) = 1 AND count(with) = 1`
  (content fence — states the exact hand and fences multi-card `with`
  inflation; it cannot detect identity across roles), and the rites keep
  their count pins; the engine-side future fix is a lint candidate (warn
  when one id fills two roles at commit) or commit-time projection.**

## Found in Phase C (the congregation + the Lifted Lamp)

- **B2 · FROZEN-QUIRK (boundary race, benign) · boundary-instant guest expiry
  vs completion order** — an `expires` due at tick T and a window completing
  at T resolve completions-first (§6.6), so a recipe's DESTROY of the
  already-expired guest is a silent no-op while its remaining outcomes (the
  BELLWOOD DRAW) still land — the win walk's guest crossing rode exactly
  this; §4/G8.
- **B4 · minor content-side input laxity (lenient domain, pre-existing) ·
  halfhour clocks cap at 47** — bare lenient clocks reject hh > 47
  (`bad clock '2:50'`, `bad clock '6:48'`); E6's "hours > 23 accepted" note
  was about the hour field — the halfhour field's own 47 cap is the real
  boundary, and day-rollover (`d:hh`) is the authored shape.
- **E10 · FROZEN-QUIRK (design) · long advances sweep the whole wheel chain
  in one pass** — back-to-back RUN chains resolve inside a single clock
  input; CS-faithful relentless needs (a `1:0` input ran silver→0 → LEAN →
  THE_BODY_FAILS end-to-end). The §7 needs-arm exception fired verbatim.
  **Disposition: DOC-NOTE** (P4's pin exploits it deliberately).

## Found in Phase D→full coverage (the CS core export)

- **E11 · ENGINE-GAP (lint) · no lint sees a never-matching `when:`** — the
  dead-recipe lint catches identical whens, post-catch-all leftovers, and
  count gates a slot's cardinality can never satisfy, but a when that is
  false for every window by negation alone (`NOT (count(actors) >= 1)`) is
  silent: the count-gate scanner checks only the inner atom, which holds.
  The converter now NEEDS the shape — CS ships requirement-less recipes its
  own first-match order can never fire (templates, epilogues, fallbacks of
  always-true parents), and the full-coverage export emits them data-dead
  under exactly such negation whens — so intentional deadness is
  indistinguishable from a typo'd gate. **Disposition: LINT candidate**
  (recognize or warn on NOT-wrapped always-true count gates; today the
  converter's header documents the marker convention).
- **E12 · ENGINE-GAP · authored outcomes cannot address the card an outcome
  just minted when the name pools** — `SPAWN X` mints into X's pool, and the
  only mint handle is `AS #id`, which is engine-written (authoring one is a
  load error); §9.38 sends a follow-up `SET X, …` to the OLDEST pool member,
  not the fresh mint. Consequence: an authored `expires` arm is impossible
  for any SPAWN/DRAW whose target pools — the CS→core export has 656 such
  instances (497 deduped recipe-effect spawn sites of stackable lifetime
  bearers over 114 elements + 159 lifetime-bearing deck entries), so
  hunger/dread/influence-class decay
  never starts for mints (the 133 authored on-expire chains arm only when
  `expires` was set some other way). Non-stackable mints are the one
  authorable tier — the §9.19 name-collision law pins the name ref to the
  fresh copy, so `SPAWN X, SET X, expires, …` is exact there — and the
  converter arms that tier; the pool tier is ledgered per instance, never
  faked. **Disposition: future engine want** — authored mint-binding (a
  binding for the card this outcome minted) or an `expires` spawn modifier
  (`SPAWN X expires 60m`); until then, arming happens engine-side (decay
  timers as content) or not at all.
