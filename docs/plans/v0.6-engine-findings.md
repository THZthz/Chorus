# Ledger — engine deficiencies & bugs surfaced by the v0.6 CS slice

The owner's mandate: authoring the slice doubles as an engine audit. Every
phase's review adjudicates each friction point as ENGINE-BUG (engine violates
its own spec), ENGINE-GAP (spec-silent, blocks natural authoring),
FROZEN-QUIRK (spec pins it; content lives with it), or CONTENT-ERROR. Engine
BUG/GAP items get a disposition: FIX (queued/landed, with commit) / IDIOM
(documented authoring shape) / LINT (content tooling) / DOC-NOTE.

## Found in Phase A (foundations + season wheel)

- **E1 · ENGINE-GAP · missing attr compares as absent, not 0** —
  `Pred::Cmp` on a living card's numeric attr yields false when the entry is
  missing (`src/core/predicate.rs` Cmp eval, "either operand missing →
  false"), while §9.31 SET-delta semantics and `total()` both treat missing
  as 0. Spec §6.3 is silent on attr-path comparisons (§9.39 pins aspects
  only). Consequence: a `silver < cost` broke-gate cannot be authored
  correctly for a first-time buyer (script entities mint empty attrs), and no
  content workaround exists.
  **Disposition: FIX LANDED** — living-card numeric attr reads read 0 when
  absent (behavior-preserving for every `>=`/`!=` gate in the two shipped
  scripts; `<` gates become correct).
- **E2 · ENGINE-GAP (minor) + IDIOM · RUN hand-off has no context binding** —
  §9.47 re-evaluates a candidate's `when:` against the post-outcome draft,
  and the shadow lint rejects identical whens, so every wheel dispatch target
  needed a synthetic world-marker when (`exists(name:THE_TURNING) AND …`,
  `count(actors) >= 1` vs `= 1` as lint noise). **Disposition: IDIOM** — the
  better content shape (keep the season card alive through its judge; judges
  gate on `exists(name:SEASON_…)`) lands with Phase B; doc note in the plan.
- **E3 · FROZEN-QUIRK · REPLACE refuses entities; trigger-body failure
  freezes the clock** — `REPLACE X WITH <entity>` refuses ("no kind",
  engine.rs REPLACE arm; §9.33 pins prototype successors), and a never-alive
  prototype inside a trigger body fails the whole advance pass forever
  (events have no window-refuse; §9.19/§9.32 severity). **Disposition:
  DOC-NOTE** (plan law 1 already pins DESTROY+SPAWN+SET restores) + future
  lint candidate.
- **E4 · FROZEN-QUIRK · silent chain death** — a weather with no matching RUN
  candidate ends the wheel with no diagnostic (§9.47's "that is CS's chain
  ending"). A content drift (rename, cardinality) would silently stop the
  seasons. **Disposition: LINT candidate** (warn on RUN-target whens with
  bare `count(role)` gates) + §8 doc note.
  **Lint cross-reference (E11's fix landed): the never-matching-`when`
  detector covers the RUN walk too — a candidate whose `when` is provably
  unsatisfiable under every selection binding (the drifted-target case this
  entry feared) is flagged at load as a lint WARNING naming the recipe, so
  the silent §9.47 chain end now leaves a load-time trace; no engine
  change.**
- **E5 · FROZEN-QUIRK (cosmetic) · follow-up rows render dead parent
  bindings** — a RUN follow-up's BEGIN row prints the parent's authored refs
  even when a bound card died mid-parent-window. **Disposition: DOC-NOTE.**
- **E6 · minor content-side input laxity** — bare clock input accepts hours
  > 23 (`0:118`) in the lenient parser. **Disposition: FIX LANDED (lenient
  domain)** — the bare lenient clock WRAPS an out-of-range halfhour field
  into whole days the way durations compose (`0:118` = 118 halfhours = day 2,
  halfhour 22; `1:49` = 97 halfhours = day 2,
  halfhour 1; `session/lenient.rs`
  `wrap_clock`, spec §11 amended). Per form: the lenient front door wraps
  (friendly, matches §9.45 duration arithmetic), the canonical `d:h @`
  passthrough keeps its frozen loud `bad halfhour` bound (§5; the frozen
  `parse_clock` tests prefer it). Absurd literals past i64 still refuse.
  B4's Phase C correction stands: the halfhour 47 cap was the real boundary;
  wrap subsumes it.

## Found in Phase B (study ladder + dreams + the Bellwood)

- **E7 · ENGINE-GAP · RUN follow-ups inherit ALL parent refs, locking the
  bootstrap card forever** — the synthesized follow-up clause carries every
  committed role (`refs_to_clause`, engine.rs:1909-1923), so the wheel chain
  (weather→time.turn→weather) keeps an open WAIT window holding
  `with=VIGOR` at all times; a restored VIGOR mint re-locks by name and
  dream.rest_vigor then §9.19-rejects. Worse, the synthesized clause is not a
  shape a player step could produce (WAIT declares actors only), so §9.47's
  "the same shape a player step produces" is violated by the implementation's
  wholesale inheritance. Bites ~70% of games (labor roll > 3).
  **Disposition: FIX LANDED** — inherited refs are PROJECTED onto the
  candidate verb's declared slots at clause build (`refs_to_clause`, engine.rs):
  a role the candidate verb does not declare is dropped from the inherited
  clause and so never locks; actors survive wherever declared (time.turn reads
  actors' silver), same-verb chains keep every role (the projection is the
  identity), the parent window's own refs and locks are untouched. Ruling 47's
  semantics bullet amended; pinned in tests/run_chains.rs (cross-verb
  projection + the slice-shaped bootstrap chain).
- **E8 · ENGINE-GAP (minor) + IDIOM · RUN candidates cannot see the parent's
  bindings** — candidate whens evaluate against the post-outcome world, not
  the hand-off, and §9.48's completion triggers (which DO see window
  bindings) fire only on BEGIN-committed cards — never on a card the parent
  just DREW. CS's dream_router shape (draw → linked keyed on the drawn
  element) is thus inexpressible in one step; the slice routes on bound-mood
  selection instead. **Disposition: FIX LANDED** — the candidate walk's
  `when:` evaluates against the post-outcome draft AND the parent window's
  committed role bindings, MERGED with the projected clause's own (engine.rs
  `apply_run`): where the candidate verb DECLARES the role the projected
  binding wins — resolved against the post-outcome draft, so the gate reads
  the follow-up's truth, not the parent's stale pre-outcome ids — and where
  the projection drops the role the parent binding stands, so a cross-verb
  gate reads the parent situation (the CS linked semantics; ruling 47's walk
  bullet amended). Same-verb chains keep their ordinary matches (the
  projection is the identity over the declared roles — the run_chains pins
  stayed green unmodified), but the declared-role bindings CHANGE SOURCE:
  they now come from the projected clause re-resolved against the
  post-outcome draft, so a same-verb gate whose bound card the parent's own
  outcomes replaced or killed reads the follow-up's truth, not the
  begin-time id snapshot (pinned: the precedence test); a role the
  projection drops is gate-visible only — the gate reads it, the follow-up
  body never carries it (an unbound-role SET silently no-ops, §9.31);
  strictness stays LENIENT, the roll binding stays None, the
  §9.50 max gate and the order-preserving first-match walk are untouched,
  §9.48's own trigger-body bindings rule is untouched, and the merge is
  eval-context only (the BEGIN row still carries the projected clause alone
  — fold symmetry pinned). Pinned in tests/run_chains.rs (the bound-mood
  dream-router dispatch, the cross-verb parent-situation gate, the
  projected-binding precedence over a destroyed-and-reminted binding).
  Still open as noted: a when keyed on a card the parent DREW (bound to no
  role) remains inexpressible — the drawn card is world-visible only
  through `count(name:…)`/`exists(name:…)` (§9.38's pool caveat applies).
- **E9 · ENGINE-GAP (input laxity) · lenient binding fills two roles from one
  card** — `alive_names` resolves each name to its OLDEST copy only
  (session/lenient.rs:384-398), so `combine the psalm and the psalm` binds
  one card twice: the combine consumes it once, mints the 6, and leaves the
  stray (bounded +4 magnitude distortion; would let a rite pool one card N
  times). **Disposition: FIX LANDED (the lenient half) + DOC-NOTE (the
  engine half stays open)** — the lenient binder now hands out DISTINCT pool
  members when one name fills several roles of one clause: authored role
  order picks copies §9.38 head-first (the first role a name ref — single
  mentions byte-identical; each further role an `#id` ref to the next living
  copy), and a pool smaller than the roles naming it refuses
  ("only one 'the psalm' — you need two"; `session/lenient.rs`
  `resolve_group`/`alive_pools`, spec §11 amended). A name doubled INSIDE one
  role still meets the engine's same-role placement refusal (the §4/G8 fence
  sentence stays true). The commit-time cross-role residue below is NOT
  addressed: canonical/scripted steps can still bind one id into two roles —
  the engine-side future fix is a lint candidate (warn when one id fills two
  roles at commit) or commit-time projection.**
  **Phase C addition — the cross-role residue.** The commit-time placement
  refusal is PER-ROLE (`placed` is a HashSet rebuilt inside each role's
  loop, engine.rs), so one card binds into two DIFFERENT roles cleanly:
  observed on the win-walk file, a lone fragment self-combines
  (`study a candle psalm with a candle psalm` → object = with = the oldest
  copy; the 2+2 pair row fires on one card, mints the 6, consumes the card
  once, leaves the second copy as a stray — a whole 2→6→18 ladder climbable
  from a single book; OBSOLETE for lenient input by this fix — the win walk
  was re-verified with the pair consuming both fragments), and same-card
  `to`+`with` is accepted on USE_ON
  (benign today — the desire cards carry no pooled magnitudes). The
  same-role placement refusal and the rite count pins do NOT cover
  cross-role: predicates have no card-identity test, so no `when:` can see
  that `object` and `with` hold the same id. **Disposition (amended): the
  STUDY pair rows now pin `count(object) = 1 AND count(with) = 1`
  (content fence — states the exact hand and fences multi-card `with`
  inflation; it cannot detect identity across roles), and the rites keep
  their count pins; the engine-side future fix is a lint candidate (warn
  when one id fills two roles at commit) or commit-time projection.**

## Found in Phase C (the congregation + the Lifted Lamp)

- **B2 · FROZEN-QUIRK (boundary race, benign) · boundary-instant guest expiry
  vs completion order** — an `expires` due at tick T and a window completing
  at T resolve completions-first (§6.6), so a recipe's DESTROY of the
  already-expired guest is a silent no-op while its remaining outcomes (the
  BELLWOOD DRAW) still land — the win walk's guest crossing rode exactly
  this; §4/G8.
- **B4 · minor content-side input laxity (lenient domain, pre-existing) ·
  halfhour clocks cap at 47** — bare lenient clocks reject hh > 47
  (`bad clock '2:50'`, `bad clock '6:48'`); E6's "hours > 23 accepted" note
  was about the hour field — the halfhour field's own 47 cap is the real
  boundary, and day-rollover (`d:hh`) is the authored shape.
  **Disposition: FIX LANDED** — see E6: the bare lenient clock now wraps
  hh > 47 into the following day(s) instead of refusing (`1:49` = day 2,
  halfhour 1), which makes day-rollover automatic; the canonical form keeps
  the loud bound.
- **E10 · FROZEN-QUIRK (design) · long advances sweep the whole wheel chain
  in one pass** — back-to-back RUN chains resolve inside a single clock
  input; CS-faithful relentless needs (a `1:0` input ran silver→0 → LEAN →
  THE_BODY_FAILS end-to-end). The §7 needs-arm exception fired verbatim.
  **Disposition: DOC-NOTE** (P4's pin exploits it deliberately).

## Found in Phase D→full coverage (the CS core export)

- **E11 · ENGINE-GAP (lint) · no lint sees a never-matching `when:`** — the
  dead-recipe lint catches identical whens, post-catch-all leftovers, and
  count gates a slot's cardinality can never satisfy, but a when that is
  false for every window by negation alone (`NOT (count(actors) >= 1)`) is
  silent: the count-gate scanner checks only the inner atom, which holds.
  The converter now NEEDS the shape — CS ships requirement-less recipes its
  own first-match order can never fire (templates, epilogues, fallbacks of
  always-true parents), and the full-coverage export emits them data-dead
  under exactly such negation whens — so intentional deadness is
  indistinguishable from a typo'd gate. **Disposition: FIX LANDED** —
  `lint_script` gained the never-matching-`when` detector as the lint's new
  WARNING class (`lint_script_findings`/`LintSeverity`; lint-scripts prints
  `[warning]` lines, the ERROR class keeps today's reporting and the
  constant-0 exit). Soundness boundary: a when is flagged only when provably
  false for EVERY §6.6 selection binding — the parsed §6.3 tree evaluated
  three-valued over the count-gate check's own §6.1 domain (slot
  cardinality; undeclared roles bind nothing), with interval narrowing per
  conjunction and role-emptiness coupling (`total(…) >= 1`, a positive path
  atom, `any`, `rel` all prove the role bound) — which catches the
  NOT-wrapped always-true count gates in all six emitted spellings,
  same-variable contradictions (`count(a) >= 1 AND count(a) < 1`,
  `total(x) >= 1 AND total(x) < 1`), and empty-vs-bound pairs. Alongside it,
  the count-gate scanner's missing `!=` arm took its arm (any authored
  `count(role) != k` used to hit the `unreachable!` and abort the whole
  lint run — reachable at HEAD, repro'd; dead iff the slot's whole range is
  the excluded value). Deliberately
  not caught (documented at `when_verdict`): world reads (`exists`,
  `count(<query>)`), `every()`'s vacuous-true corner, non-int comparisons,
  and the E7 RUN-projection re-evaluation against parent bindings — the
  same simplification the count-gate check has always made. Note that the
  WARNING class WIDENS that corner's exposure: a cross-verb RUN candidate's
  runtime count can sit outside its own slot range (the parent's committed
  bindings are projected, not re-validated), so a statically-dead count
  atom may actually HOLD there — what the ERROR class always assumed now
  also underwrites warnings. Tolerance by
  design, pinned as a composition in tests/convert_cs_smoke.rs (0 errors):
  cultist-full.txt carries 36 deliberate dead-marker twins (all `.x2`, the
  converter's marker convention) PLUS 40 NOT-alt total contradictions the
  detector surfaces as a byproduct, split by which side is dead
  (E12-style honesty): 24 GENUINELY CS-DEAD — the society family, whose own
  `society >= 1` contradicts its naming parent's precondition
  (`talktofollower` runs only under `society < 1`), so even CS's alt
  routing cannot reach it; and 16 CONVERTER-INDUCED — the summoned family,
  whose own requirements are satisfiable but which is the fallback alt of
  TWO mutually exclusive parents (`talktofollower` {summoned:-1} vs
  `talktospirit` {summoned:1}): `apply_alt_gates` (convert_cs.py) conjoins
  one NOT(parent-requirements) per naming parent, so the stacked negations
  never hold — a routing fidelity loss the port carries, not CS deadness.
  cultist-slice and the-nightjar-flyer stay 0-error 0-warning.
- **E12 · ENGINE-GAP · authored outcomes cannot address the card an outcome
  just minted when the name pools** — `SPAWN X` mints into X's pool, and the
  only mint handle is `AS #id`, which is engine-written (authoring one is a
  load error); §9.38 sends a follow-up `SET X, …` to the OLDEST pool member,
  not the fresh mint. Consequence: an authored `expires` arm is impossible
  for any SPAWN/DRAW whose target pools — the CS→core export has 656 such
  instances (497 deduped recipe-effect spawn sites of stackable lifetime
  bearers over 114 elements + 159 lifetime-bearing deck entries), so
  hunger/dread/influence-class decay
  never starts for mints (the 133 authored on-expire chains arm only when
  `expires` was set some other way). Non-stackable mints are the one
  authorable tier — the §9.19 name-collision law pins the name ref to the
  fresh copy, so `SPAWN X, SET X, expires, …` is exact there — and the
  converter arms that tier; the pool tier is ledgered per instance, never
  faked. **Disposition: FIX LANDED (recipe-spawn half: 497 sites armed via
  the SPAWN `expires` modifier; remaining: 159 deck-entry mints — DRAW has
  no expires arg — and the general mint-binding want) —** the authored
  `expires <duration>` modifier (`SPAWN X expires 60m`, the design's second
  option; parse.rs `spawn_args`, engine.rs `apply_spawn`) arms the mint at
  BIRTH with the SET-expires pair — the §9.36 key, the one §9.45 duration
  parser, the same checked arithmetic (one shared `materialize_expires`
  write with SET) — anchored to the mint clock (`ctx.now`: the window's
  START clock inside a completion, §6.7). Each SPAWN arms its own fresh
  copy, so pooled mints arm per instance and the oldest-name trap is gone;
  INTO-targeted spawns arm the same way; a bad duration gets the same loud
  rejection SET-expires gives (bare non-durations fail at parse, quoted
  non-durations refuse the window, §9.36). Concretization needs no new row
  kind: the pair rides the concrete SPAWN's `attrs=` materialization
  (§9.18 — spec rulings 18 and 36 extended, no new ruling number), so the
  fold replays byte-identically.
  **Converter half landed (the recipe-spawn arm closed):** convert_cs.py's
  `lifetime_arm` now rides the modifier on EVERY recipe-effect mint of a
  lifetime bearer — `SPAWN X expires <dur>`, the CS lifetime at the 1s→1min
  scale in §9.45 canonical rendering — replacing both the old
  SET-after-SPAWN shape (the modifier needs no §9.19 pin, and arms pooled
  mints the SET could never address) and the recipe-effect E12 ledger line.
  Census: armed 0 → 497 deduped (recipe, element) sites — 582 armed mint
  instances on the generated file over 446 recipe lines (sites weighted by
  effect magnitude, re-emitted on alt/run copies), pinned both in the
  converter's census asserts and in tests/convert_cs_smoke.rs, with the
  decay economy proved live: the bare-start WAIT wheel falls to
  `wait.alt.starvation`, whose HUNGER mint carries `expiresAt` = the
  window's START clock + 60 authored minutes, and the authored
  `exp_hunger` DESTROY+SPAWN DECREPITUDE chain fires at the first halfhour
  boundary at or after `expiresAt`; the whole log folds identically. The
  133 on-expire chains and the on-complete trigger bodies keep their own
  SET-expires arming, untouched. Remaining (the open half): the 159
  deck-entry mints — DRAW has no expires arg, the modifier is SPAWN-shaped
  by design (a DRAWed lifetime bearer arms only if its deck entry's
  prototype `with` pre-arms, or by a following SET) — and the general
  mint-binding want (a handle for the card this outcome minted, addressable
  by later outcomes).
