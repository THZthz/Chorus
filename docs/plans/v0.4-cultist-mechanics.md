## 0. Invariants every feature must preserve (the determinism laws)

1. `state` is a fold of the append-only log; `fold(loadLog(saveLog(log))) === played
   state` byte-for-byte, including `fired`, `ended`, and everything new below.
2. Concrete log rows always round-trip: `format(parse(row)) === row`. (Round-trip is
   asserted only on engine-written rows; script-sourced outcome strings are never
   formatted — F3's canonical-equals-expansion deviation is therefore safe.)
3. The engine never re-derives randomness or arithmetic at replay — concrete rows carry
   results (SET deltas → absolute values; ROLL → ROLLED; DRAW → DRAWN+SPAWN).
4. Steps are atomic: any application failure → whole step rejected, nothing logged,
   clock unmoved; REFUSE discards the draft (logged, zero time).
5. No RNG outside the recorded-counter mechanism of F4.
6. **NEW (review F0-3): draft discipline covers the new state.** `cloneState`
   (fixed field list, types.ts) must deep-copy `byName` pool ARRAYS (a shallow
   `new Map` shares arrays between draft and real state — a discarded draft's pool
   destroy would mutate real state) and copy `rng`/`decks`. All THREE test-local
   `snap()` helpers (test/engine.test.ts, test/endings.test.ts,
   test/nightjar-explorer.test.ts) gain `rng` and `decks` — consolidate them into one
   shared test helper (test/snap.ts) so this can't drift again.

## 1. F1 — stackable cards (multiple same-name instances)

Today names are unique among the living (`addEntity`, types.ts; duplicate SPAWN
rejects). CS models Dread/Funds as pools of identical cards.

**Declaration**: keyword `stackable` on entity/prototype lines, before `with`:

```
entities:
  SUSPICION is state stackable with suspicion:1
prototypes:
  RUMOUR is idea stackable deriving name from object
```

**Data path (review F-8)**: `stackable` parses into `EntitySpec`/`PrototypeDef` and
lands on compiled content as two derived sets: `stackableNames` (declared prototype /
entity names) and `stackableKinds` (kinds of stackable declarations). `addEntity`
gains an `isStackable` flag; every mint site (SPAWN, REPLACE, DRAW/SPAWN) computes it:
`SPAWN NAME` → NAME ∈ stackableNames; `SPAWN kind:K` → K ∈ stackableKinds.
Entity/prototype line parsers must learn the keyword (today the leftover-text check
throws on it).

Semantics:
- `State.byName` becomes `Map<name, id[]>` (append on spawn, remove on destroy;
  insertion order = birth order). Uniqueness law unchanged for non-stackable names; a
  stackable spawn never collides with itself, but MAY NOT collide with a distinct
  non-stackable living name (shared namespace).
- **Pool addressing rule**: a name ref resolving to N > 1 living copies addresses the
  OLDEST copy — defined as the HEAD of the byName array (insertion order; NEVER
  compare id strings, which sort wrong across records: `e10_1` < `e2_1`). Applies to
  DESTROY, SET, MOVE, REPLACE, ref positions, lenient resolution, and `inspect()`.
- **Ripple list (review-verified, complete)**: `addEntity` (flag), `resolveRef`,
  SPAWN collision check, **DESTROY name-release** (`byName.get(e.name) === e.id`
  breaks under arrays — becomes array removal), **REPLACE collision check + release**
  (engine unlisted before — stackable-aware), **built-in expiry** (see below),
  `exists()`, `lenient.aliveNames()` (currently map-set overwrites duplicates —
  last-wins; must keep arrays and resolve oldest), TUI listing/tab completion
  (cosmetic duplicates OK), `inspect()` (first-visible → oldest), predicate `exists`.
- **Engine-built destroys address by id (review D-2)**: the built-in expiry path
  constructs `DESTROY nameRef(e.name)` — under pools that kills the oldest copy while
  the real expiring card re-fires forever. Rule: engine-written destroys keyed to a
  specific entity (built-in expiry) concretize to `DESTROY #id`. Authored
  `DESTROY <poolname>` stays name-addressed (oldest) and logs the name ref. Test: two
  copies, the YOUNGER carries expires → exactly the younger dies, one crossing, done.
- REPLACE of a stackable with its own prototype now succeeds (spawn appends, destroy
  pops the old head) — §9.33's rejection note is updated accordingly. [doc: next pool
  op then addresses the next-oldest — state in the ruling.]
- [doc] Lenient input can only address the oldest copy by name (#id is the escape
  hatch); journal prose renders two pool copies in one role as "SUSPICION and
  SUSPICION"; SET-by-name touches only the oldest. All three go in the ruling.

**Companion — counting the pool**:
- `src/query.ts` gains a `name:<x>` term, **exact-case** (matches the name-ref/exists
  convention — resolves the plan's internal contradiction), negation `-name:x` works.
- `count(...)` overloaded in the SHARED value-expression evaluator (so
  `ROLL(count(name:X), 6)` also parses): `count(role)` (existing) vs `count(<query>)`
  where the arg starts with a query-term starter. **Load-time arg validation** for
  `count()`/`total()`: the argument must be a declared role or a query-starter —
  `count(DREAD) >= 3` (the most tempting typo) is a load error naming the valid
  forms, with a test.

Tests: spawn N copies (byName/listing/inspect show N); oldest-copy DESTROY twice;
collision with non-stackable name rejects; engine-expiry kills the YOUNGER copy by id;
younger-expires-doesn't-reFire; `count(name:x)` thresholds select recipes;
`count(DREAD)` load error; slot holds two same-named copies; name release when the
last copy dies; REPLACE self-replace succeeds; fold/JSONL equality (snap incl. new
fields); REFUSE-after-pool-destroy leaves the real pool untouched (deep-copied
arrays). Migrate the ~15 `byName.get(name)!` test call sites to oldest-copy access.

## 2. F2 — conditionals: IF / ELSE IF / ELSE in outcome lists

Grammar (branch bodies REQUIRE parens; `IF` intercepted at the top of `outcome()`,
ELSE chain consumed greedily inside the IF node):

```
outcome += "IF" predicate "->" "(" outcomes ")"
           ( "ELSE IF" predicate "->" "(" outcomes ")" )*
           ( "ELSE" "->" "(" outcomes ")" )?
```

Semantics:
- Conditions use the full §6.3 grammar. **Parsing (review F-9)**: predicates are
  string-tokenized today; IF conditions need a Tok-stream predicate path, consuming
  the condition as a balanced unit up to depth-0 `->` (predicates contain commas via
  `rel`/`every` — naive comma-splits are wrong). **`roll` needs a ValExpr variant**
  `{t:'roll'}` plus an eval-context field (PredCtx extension ripples to every
  evalPred call site).
- Evaluation: in order, against the DRAFT (earlier outcomes in the same list are
  visible to later IFs). Normative examples for the doc: (a) selection ran against
  INPUT state but branches run against the DRAFT — `when count(name:S) < 3` fires,
  its own `SPAWN SUSPICION, IF count(name:S) >= 3 -> (ENDING ARRESTED)` arrests in
  the same step; (b) an IF after `DESTROY OBJECT` in the same list reads a
  dead-stamped entity (comparison → false, silently) — documented behavior.
- **Asymmetric failure discipline [doc]**: the same predicate grammar returns false in
  `when:` positions on unresolvable refs, but REJECTS the step in IF conditions —
  deliberate; document.
- **Concretization**: the log records ONLY the taken branch's outcomes, flattened in
  position. Test asserts the recorded (taken-branch) sentence round-trips — the
  authored IF never reaches the log (journal-loss corollary documented in §5.3
  terms).
- **Recursive guards (review F-0, P0)**: the trigger PROGRESS/REFUSE guards and
  `checkEndingRefs` are shallow top-level scans today — nested IF branches and
  function expansions would escape all three. This commit rewrites them to recurse
  into IF branch bodies; ordering with F3: expansion happens BEFORE the guards run.
- Role-dependent operands (`count(role)`, `total(role,…)`, `role.aspect.x`,
  `rel(…role…)` — anything reading bound roles) inside slot/expiry TRIGGER outcome
  conditions are a **load-time error** (they would silently evaluate false — review
  D-6; precedent: the PROGRESS/REFUSE trigger guards).
- `roll` binding (review D-5): stored on the apply ctx (NOT State — dies with the
  draft on REFUSE), **reset per clause** of a multi-clause step, survives function
  expansion boundaries. Compile-time `roll`-without-possible-ROLL lint is best-effort
  (branch-descending may-bind analysis, false negatives allowed); unbound `roll` in a
  taken branch at runtime = §9.19 step rejection.

Tests: branch order (first true wins; ELSE default); draft-visibility (SET then IF);
concretized record = taken branch only + fold equality; recorded-form round-trip;
trigger + expiry lists accept IF; role-operand-in-trigger = load error; nested-guard
regression (PROGRESS inside IF inside trigger = load error); REFUSE inside a branch;
round-trip of recorded rows; unbound-roll runtime rejection.

## 3. F3 — functions: parametric outcome macros

```
functions:
  sus capital -> SPAWN SUSPICION, NARRATE "The conductor's eyes linger on {capital}."
  watch(n) -> IF count(name:SUSPICION) >= n -> (ENDING ARRESTED)
```

- Section `functions:`; line = `NAME(params…) -> OUTCOMES`. **Plumbing (review F-13)**:
  functions parse BEFORE verb/trigger bodies in `compileContent`; the function table
  threads into `parseOutcomes` as an explicit parameter (not Dictionary state).
- **Call-site dispatch**: at the top of `outcome()` with a name-then-`(` lookahead;
  known function names win before op parsing; unknown `NAME(...)` in outcome position
  = compile error listing the vocabulary; declaring a function named like an outcome
  op = compile error (`dict.isOp` check).
- **Two substitution mechanisms (review D-1, P0)** — the plan's flagship example was
  broken without this: (a) AST-level: a param may stand anywhere a ref or value
  literal is expected (ref, role, int, delta sign, string, bool, dur, key, into,
  pair positions); kind errors surface at runtime as usual step rejections. (b)
  STRING-interpolation: `{param}` inside a quoted string IN A FUNCTION BODY is
  rewritten at expansion to the call-site arg's canonical spelling (baked at compile:
  `sus(THE_GUARD)` renders "…linger on THE_GUARD."). Reserved tokens — `{actors}`
  … `{to}`, and `{roll}` — are NEVER param-substituted and pass through; an
  undeclared `{token}` in a body string is a load-time warning. The
  expansion-equivalence test compares against a twin with the substituted string.
- Nesting allowed; **recursion = cycle detection (colored DFS over the call graph),
  load error naming the cycle** (review D-12); depth > 8 = nesting-cap load error for
  legitimate chains; **arity mismatch = load error**; a param shadowing an entity
  name resolves to the param inside the body (documented).
- Role refs in bodies resolve per call site (fine in recipes; runtime rejection in
  triggers — documented). ROLL/IF/DRAW legal in bodies.
- Expansion happens BEFORE the trigger guards and checkEndingRefs run (ordering with
  F2's recursive guards).
- Canonical-form deviation: calls never appear in logs; canonical = expansion
  (verified safe — nothing formats script-sourced outcomes).

Tests: expansion equivalence (call vs hand-expanded twin, string-substitution case
included); nesting; cycle load error (a↔b); depth cap; arity mismatch; param
shadowing; trigger call sites; unknown-function compile error; op-name collision.

## 4. F4 — seeded dice: ROLL, `roll` values, tiers via F2

**RNG mechanism (the only randomness in the engine)**:
- Script meta `seed: N` (default 0), stored in content. `State.rng` = integer
  counter, starts 0, included in snap; cloned by cloneState (law 6).
- Sampling is counter-based and pure: die i of a roll at counter c is
  `1 + floor(N * splitmix64(seed ⊕ c+i) / 2^64)` — **BigInt end-to-end** (target
  ES2022, Node ≥ 22; review F-4 recommendation), never through float64 narrowing; a
  test-vector table pins (seed, counter, sides) → value. A roll of m dice consumes
  exactly m counter values.
- Concretization: ROLL → engine-written `ROLLED(<total>, <ctrAfter>)` — fold's apply
  sets `state.rng = ctrAfter`, nothing else. **ROLLED/DRAWN need real parse+format
  entries** (review F-4: without them every record round-trip fails — format's
  generic fallback emits unparseable rows); authoring them is a compile error
  (paren-form-error precedent). Undo claim verified sound: foldUpTo re-folds the
  remaining log through applyRecord, so the counter lands exactly where the folded
  history left it.

**The op**: `ROLL(<count-expr>, <sides-expr>[, <bonus-expr>])`.

**Parsing (review F-15)**: the generic paren'd-arg machinery cannot parse
`ROLL(total(actors, aspect:nerve), 6)` (no depth tracking, commas inside nested
parens) — ROLL gets its own depth-aware value-expression parser over Toks;
EVALUATION reuses the §6.3 evaluator (extended by F1's `count(<query>)` and F2's
`roll`). Runtime validation: sides < 2 or count < 0 → step rejection; count = 0
allowed (total = bonus or 0).

- `roll`: reserved operand, usable in conditions and **NARRATE strings only**
  (`{roll}` in PROGRESS/REFUSE strings = load-time error — review D-13); rewritten
  AT EXECUTION so the concrete row carries the number; last-wins within one outcome
  list, rebinds on a second ROLL. [doc] A NARRATE `{roll}` in a REFUSED step is
  journal-visible but the counter never moved (draft died) — the "same dice" re-roll
  oddity is documented, deterministic, and accepted.

**Triggers roll** (the trigger-检定 requirement): slot/expiry outcome lists may
ROLL/IF; the EVENT record carries the concrete outcomes incl. the ROLLED row and
replays exactly. World-check triggers need no dice: `IF count(name:X) >= 3 -> …` /
`IF exists(...) -> ...`.

Tests: determinism (same seed → identical dice); vector table; counter reconstruction
through undo (roll, undo past it, different roll — snap equality vs fresh run);
ROLLED round-trip + authoring rejection; tier selection incl. bonus and 0-dice;
sides/count rejections; {roll} interpolation in concrete journal + PROGRESS/REFUSE
load error; trigger rolls replay through EVENT rows; REFUSE-after-ROLL leaves counter
unmoved in play AND fold; grep gate: no Math.random in src.

## 5. F5 — decks (牌堆)

```
decks:
  RUMOURS spec RUMOUR, RUMOUR, HEARSAY, SCANDAL defaultcard RUMOUR reset
```

- New script section `decks:`; spec entries are **prototype/entity NAMES only**
  (kinds dropped from the grammar — review D-10c), resolved at load via a new
  post-parse check modeled on `checkEndingRefs` (none exists to reuse); repeats
  weight the draw.
- **Permutation semantics (review D-10)**: the fixed draw order is a permutation over
  POSITIONS of spec (multiset preserved — `A, A, B` keeps 2:1 weighting), derived
  purely from (seed, deck id) at load, identical at play and fold, consuming NO rng
  counter. `State.decks[id] = cursor`; a draw serves `perm[cursor]`, cursor+1.
  Exhaustion: `reset` → wrap to 0 (the sequence is periodic with period len(spec) —
  the plan's earlier "non-cyclic variety" claim is deleted); else `defaultcard`
  forever; with neither → DRAW fails → step rejected (§9.19). [doc] Seed changes
  shift future permutations/dice but never past rows — asymmetric drift under §9.30.
- Op: `DRAW <DECK> [INTO <ref>]` (INTO default reuses SPAWN's at-card-else-actor
  logic; **in trigger context bindings are empty — the nightjar trigger DRAW authors
  an explicit INTO**). Concretizes to `DRAWN(<DECK>, <name>)` + the standard concrete
  SPAWN; fold: DRAWN advances the cursor (asserting the name matches the permutation
  — content drift fails loud), SPAWN replays normally. DRAWN engine-written only.
- **Livelock rule (review D-11)**: deck entries should be stackable, or consumed/
  renamed on the same step — a non-stackable entry whose previous copy still lives
  makes every draw fail identically forever (cursor never advances). Documented as an
  authoring rule with a test pinning the stuck-state error message.
- Deck cards are ordinary entities once drawn (stackable decks compose with F1).

Tests: permutation determinism (same seed → same order; multiset weighting intact);
cursor reconstruction through JSONL fold (snap incl. decks); exhaustion →
reset/defaultcard/rejection; DRAWN+SPAWN atomicity; non-stackable livelock message;
DRAW inside a trigger (explicit INTO); load-time spec validation; fold equality.

## 8. Settled by fiat (challenged and upheld by review, or amended)

- Pool addressing = oldest copy = **byName insertion order** (id-string comparison
  rejected by review). Alternatives rejected: REFUSE on ambiguity; random copy.
- Engine-written destroys (built-in expiry) address by #id; authored name destroys
  address the oldest. (Review D-2.)
- IF concretizes to the taken branch only (alternative: log the IF and re-decide at
  fold — rejected; consistent with SET deltas and recipe-id recording).
- Deck order = seed-fixed position permutation, periodic under reset; no mid-run
  reshuffles (recorded-shuffle-stream deferred as scope creep).
- `roll` is a last-wins ctx binding scoped to one outcome list, reset per clause
  (named `AS` bindings deferred).
- Functions are compile-time macros with both AST and string substitution; cycles are
  load errors via DFS, depth 8 is the chain cap.
- Canonical-form deviation: calls never appear in logs.
- IF-condition failure = step rejection vs `when:` false — deliberate asymmetry,
  documented.
